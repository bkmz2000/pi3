# pi3 — API v1 + Friendly Errors Plan

Combined plan: finalize the kid-facing basic API ("API v1") and overhaul the
friendly-error pipeline (full i18n + pattern-based hints). Executed by Claude
(Sonnet 4.6) in Claude Code, one phase per session/PR, in order A → F.

This plan follows the **Ground rules** section of `pi3-fix-plan.md` verbatim
(one phase = one PR; verification gate `npm run typecheck && npm run lint &&
npm run test:ci && npm run test:server:ci`; coverage ratchet; docs-sync rule;
VERIFY means run it and read the output).

## ⚠️ The one breaking change — read first

Phase B removes automatic velocity integration (`_apply_velocity` is currently
called for every actor each frame from `_tick`, graphics/__init__.py ~line
1360). After this lands, **every existing student project that sets `vx`/`vy`
stops moving** until it calls `actor.move()` in its tick. The bundled examples
are migrated in Phase C, but student projects on the server are not. This is
acceptable NOW (one lesson of student work exists) and unacceptable after
launch — which is the whole reason to ship this plan before more lessons run.
The human will announce the change to students; the plan does not attempt
compat shims. Do not add one.

## Locked design decisions (do not relitigate during execution)

1. `move()` (no args) applies `vx`/`vy` once. It is the manual physics step.
2. `forward(distance)` moves along the facing direction, implemented as
   `self.pos += Polar(self.angle, distance)`. The docstring shows this body
   verbatim — it is teaching material. There is NO overloaded `move(distance)`
   and no `move_forward`.
3. `State` is a library class (exported), used by kids at module level
   (`state = State(score=0)`) and used internally as the storage for an
   actor's custom attributes. Kid-facing actor construction stays flat:
   `Actor(hp=100, gold=0)` — no `state=` kwarg in examples or docs.
4. Actor attribute sets are **closed after construction**: custom attributes
   are declared via constructor kwargs (or assigned inside the `init()` hook);
   after `__init__` completes, reading or writing an undeclared attribute
   raises a friendly did-you-mean error. Mid-game `player.combo = 0` is an
   error whose message teaches the fix.
5. Removed from the API: `change_x_by`, `change_y_by` (actors/__init__.py
   ~280–289), `Window.size()`, `Window.run()`, `Window.stop()` (the global
   functions remain; Window keeps `width`/`height` properties and anchors).
6. Removed from `__all__` (still importable explicitly, kept in advanced
   docs): `push`, `pop`, `translate`, `rotate`, `scale`. This resolves the
   `rotate(45)` vs `ship.rotate(45)` collision for star-import beginners.
7. Added to the API: `clamp(value, lo, hi)`, `randint(low, high)` (int,
   inclusive), `pick(sequence)`, `Mouse.pos` (Vector2), `actor.bounce()`,
   `actor.keep_in_bounds()`, `actor.distance_to(target)`, `Timer` added to
   `__all__`. `random()` is unchanged.
8. Position polymorphism: `point_towards`, `move_to`, and `distance_to` all
   accept — an Actor, the `Mouse` singleton, a `Vector2`/`Point`, an
   `AnchorPoint`, an `(x, y)` tuple, or two numbers. One shared resolver.
9. All library-raised teaching errors flow through one mechanism: a
   `FriendlyError` exception carrying `messageKey`/`messageArgs`/`suggestions`.
   Python never produces human-language sentences; the frontend renders all
   text through i18next. English may appear only inside `raw` tracebacks.
10. Error-hint patterns take precedence over CPython's native hints (CPython's
    "Perhaps you forgot a comma?" for `Mouse x` is actively wrong).

### B3. Closed actor attributes
Rework `Actor.__init__` / `__setattr__` / `__getattr__`:
1. During `__init__` (including the `init()` hook call at its end), all
   assignment is free. Set `object.__setattr__(self, "_sealed", True)` as the
   LAST line of `__init__` — after `init()` returns.
2. Constructor kwargs: names matching a class property → routed through the
   property (current behavior). Other names → stored as custom attributes
   (implementation detail: an internal `State`; expose it as `actor.state`
   read-only property for future tooling, but do not document it in the
   beginner tier).
3. Constructor kwarg names within Levenshtein distance ≤ 2 of an
   `ACTOR_BUILTIN_ATTRS` name → raise FriendlyError
   (`friendlyError.naming.actorKwargTypo`, `{got, candidate}`). Distance > 2 →
   legitimate custom attribute, accept silently. Rejecting (not warning) is
   deliberate: a typo'd kwarg otherwise becomes a permanently declared wrong
   name. Exact matches of builtin names are properties (case 2), so only
   near-misses can reach this check.
4. `__setattr__` after seal: name is a property, in `__dict__`, starts with
   `_`, or is a declared custom attr → set normally (keep this fast path
   FIRST — it runs every frame). Unknown name → FriendlyError
   `friendlyError.naming.actorSealed`, args `{name, candidates}` where
   candidates = Levenshtein over (builtins ∪ declared customs); the message
   teaches: "declare it when the actor is created: Actor(..., {name}=0)".
5. `__getattr__` on miss: same key family (`actorUnknown`), same candidates.
6. **Subclass check:** `Snake(Actor)` assigns new attrs inside `init()` —
   covered by sealing AFTER `init()`. Add a test for exactly this. Also test
   that `self.x = ...` inside `update()` (a sealed-phase write to a builtin)
   still works through the property.

### B4. New helpers
1. `clamp(value, lo, hi)`, `randint(low, high)` (inclusive, returns int),

2. `Mouse.pos` property returning `Vector2(_mouse_x, _mouse_y)`.
3. Shared resolver `_resolve_xy(args, kwargs) -> (x, y)` accepting the forms

4. `actor.distance_to(target)` → float, via resolver + `Vector2.distance_to`.
5. `actor.bounce()` → reflects `vx`/`vy` off the window edges using the

   the bounds API; fall back to a small default if no collider shape set),

6. `actor.keep_in_bounds()` → clamps position only (no velocity change),

7. Add `Timer` to `__all__`.

## Phase E — Syntax & naming pattern table

1. **Unify the duplicate classifiers.** Extract
   `classify_syntax_error(source: str, exc: SyntaxError) -> dict(key, args,
   fix?)` into a new `src/assets/python/syntax_hints.py` (worker FS-write +
   raw-import wiring, as in Phase A step 4). Both `linter.py`'s E999 branch
   and `error_hook.py`'s grammar branch call it; delete their private elif
   chains. Existing E999* keys keep working through it.
2. Patterns, in precedence order (first match wins; all line-local around
   `e.lineno`/`e.offset`; each ≈10 lines + fixtures):
   - **E999SmartQuotes** — `e.msg` contains "invalid character" and the char
     is one of `«»""''„`. Args `{char}`. Fix: replace all typographic quotes
     on the line with `"`.
   - **E999ImportEmpty** — `e.msg` contains "after 'import'" OR line matches
     `^\s*from\s+\w+\s+import\s*$`. Fix: append `*` when the module is
     `graphics`; generic message otherwise.
   - **E999MissingDot** — tokenize-or-scan the error line for `NAME NAME`
     where first ∈ `NAMESPACE_ATTRS` and second ∈ its attribute list (from
     the manifest). Args `{obj, attr}`. Fix: insert `.`. MUST fire before any
     passthrough of CPython's "Perhaps you forgot a comma?".
   - **E999AssignInCondition** — `e.msg` contains "Maybe you meant '=='"
     (CPython ≥3.10 detects it; we translate it). Fix: `=` → `==`.
   - **E999MissingCallParens** — line matches
     `^\s*(NAME)\s+[^=(]` where NAME ∈ manifest exported callables. Args
     `{func}`. No auto-fix (argument span is ambiguous).
   - **E999DefParens** — `def NAME:` without `(` → message + fix `()`.
   - Fallback: existing E999* mapping, then generic E999.
3. **Homoglyph detection** — lives in the NAMING path, not syntax: in
   `error_hook`'s NameError/AttributeError handling AND `linter.py`'s F821,
   before Levenshtein: if the unknown token contains Cyrillic codepoints and
   homoglyph-transliteration yields a known name (manifest ∪ user's own
   names — the linter already tracks user scope; error_hook has the globals),
   emit `friendlyError.naming.wrongLayout`, args `{got, fixed}`, with
   one-click fix. Table (both cases):
   `а→a с→c е→e о→o р→p х→x у→y к→k в→b н→h т→t м→m и→u г→r` (lowercase) and
   `А→A В→B С→C Е→E Н→H К→K М→M О→O Р→P Т→T Х→X У→Y`. The ru message must
   explain the *layout* cause, not just suggest the name — that is the entire
   point of the pattern.
4. Each pattern: fixture test (source string → expected key + args + fix) in
   the python validation harness; plus one end-to-end check per pattern
   family through `lint()` and one through the runtime path, asserting both
   produce the SAME key (the unification guarantee).
5. Add all new keys to en.json + ru.json + the Phase D registry.
6. `graphicsDocs`/concepts untouched — patterns are invisible until they fire.

## Phase 1 — Make Stop always work (P0)

**Why:** In production, COOP/COEP headers are never set, so
`crossOriginIsolated` is false, `SharedArrayBuffer` doesn't exist, and
`pyodide.setInterruptBuffer` is never installed. A busy loop
(`while True: pass`) executes synchronously in the worker, so the worker's
`interrupt` message handler can never run (messages queue behind running
Python). `RunnerProvider.interrupt()` has a 150 ms fallback that resolves the
promise and flips UI state — but the worker stays stuck forever. There is no
`worker.terminate()` anywhere in the codebase.

The fix has two independent halves. Do both:
- **1A:** Serve COOP/COEP headers in production so the interrupt buffer works
  (graceful interrupt becomes the fast path).
- **1B:** Add a terminate-and-respawn escalation so Stop works even when SAB is
  unavailable (old browsers, misconfigured proxy, dev mode).

### 1A — COOP/COEP headers in Express

**File:** `server/index.ts`. The static serving is at the bottom
(`app.use(express.static(DIST_DIR))` ~line 134 and the SPA fallback
`app.get('*')` below it).

Steps:
1. Add a middleware BEFORE `express.static` and BEFORE the SPA fallback that
   sets on every non-API response:
   ```
   Cross-Origin-Opener-Policy: same-origin
   Cross-Origin-Embedder-Policy: require-corp
   ```
   Do NOT set these on `/api/*` responses (not needed, and COOP on OAuth
   redirect responses is untested territory — keep the change surface minimal).
2. **OAuth check (critical):** the login flow is full-page redirect
   (`GET /api/auth/login` → Loginus → `GET /api/auth/callback`), not a popup,
   so COOP `same-origin` is safe. VERIFY by reading
   `server/routes/auth.ts` — confirm there is no `window.open` /
   postMessage-based flow anywhere in `src/components/user/`. If you find one,
   STOP and report instead of proceeding.
3. **Cross-origin subresource audit:** with `require-corp`, every cross-origin
   resource must be CORS/CORP-clean. Audit what the built app loads:
   - Local `/pyodide/*` — same-origin, fine.
   - CDN fallback `cdn.jsdelivr.net` — loaded via dynamic `import()` (CORS
     module request) and `fetch` inside Pyodide; jsDelivr serves
     `Access-Control-Allow-Origin: *` and CORP headers. Should work, but
     VERIFY in step 5 by blocking `/pyodide/*` (rename the dir temporarily in
     `dist/`) and confirming the CDN path still boots with headers on.
   - `grep -rn "https://" src/ index.html --include="*.ts" --include="*.tsx" --include="*.html" | grep -v jsdelivr | grep -v "://localhost"` —

### 1B — Hard-kill escalation in the runner

**Files:** `src/runner/RunnerProvider.tsx` (worker lifecycle:
`getWorker()` ~line 313, `interrupt()` ~line 478, `attachCanvas()` ~line 507,
module-level `canvasTransferred` flag), `src/CanvasWindow.tsx` (canvas element
+ `attachCanvas` effect, ~lines 12–74), `src/runner/worker.ts` (init flow),
`src/runner/WorkerInterface.ts` (if new events needed).

**The OffscreenCanvas trap (do not skip):**
`canvas.transferControlToOffscreen()` can be called **once per canvas
element**. After `worker.terminate()`, the old OffscreenCanvas dies with the
worker and the existing `<canvas>` DOM element is permanently unusable for
transfer. The respawn design MUST force React to mount a **fresh canvas
element**.

Design:
1. Add to `useRunnerStore`: `workerEpoch: number` (starts 0).
2. In `CanvasWindow.tsx`, key the canvas element by epoch:
   `<canvas key={workerEpoch} ...>` and make the `attachCanvas` effect depend
   on `workerEpoch` so a remount re-runs transfer + event wiring.
3. In `RunnerProvider.tsx`, implement `hardKillWorker()`:
   - `worker.terminate()`; set module-level `worker = null`,
     `canvasTransferred = false`, `interruptBuffer = null`.
   - Reset Pyodide-ready state in the store (`ready: false`,
     `running: false`, clear `inputPrompt`, `canvasActive`).
   - Increment `workerEpoch`.
   - Call the existing init path so the next `getWorker()` re-creates the
     worker, re-posts `init` (Python module sources), re-sends
     `set_interrupt_buffer` (the existing setup function that creates the SAB —
     factor it so it can be called again), and the keyed canvas remount
     re-transfers a fresh OffscreenCanvas.
   - VERIFY in code: the `init` command payload (graphics module sources) must
     be re-sendable — find where `init` is first posted and ensure the sources
     are still available at respawn time (they're static imports, so yes, but
     confirm the function is reachable/factored, not inlined in a
     mount-once effect).
4. Rewrite `interrupt()` as escalation:
   - If `interruptBuffer` exists: set `buffer[0] = 2`, post `interrupt`, wait
     up to **500 ms** for `interrupt_ack`. On ack → done (graceful).
   - If no buffer OR no ack within 500 ms → `hardKillWorker()`, then resolve.
   - Surface state to the user: while Pyodide reloads after a hard kill, the
     Run button should show the existing loading state (`ready: false` already
     drives this — verify it does).
5. Pyodide reload after a hard kill takes seconds. That's acceptable — it
   replaces "reload the entire page and lose console output." Do NOT try to
   keep a warm spare worker in this phase (out of scope).

**Tests (required, bump ratchet):**
- Unit-test the escalation logic in `RunnerProvider` using the existing
  synthetic-`WorkerEvent` pattern documented in CLAUDE.md ("Testing the worker
  without Pyodide"). Mock `Worker` with a controllable stub:
  - ack within 500 ms → no terminate, no epoch bump.
  - no ack → terminate called once, epoch bumped, state reset.
  - no SAB (`interruptBuffer === null`) → straight to terminate path.
- Add a Puppeteer E2E in `tests/puppeteer/`: run `while True: pass`, click
  Stop, assert the IDE can run `print("alive")` afterwards **without page
  reload**. Wire it into the docker-e2e suite if the harness supports it;
  otherwise add as a standalone script and note it in CLAUDE.md.

**Docs:** update `CLAUDE.md` "Dev vs Production" section (headers now set in
both dev and prod server) and `todo.md` (check off the SharedArrayBuffer item).

**Acceptance:**
- Production build: `crossOriginIsolated === true`.
- `while True: pass` + Stop → IDE usable again, no reload, in BOTH the
  graceful path (headers on) and the hard-kill path (test by launching the

## Phase 5 — Replace the input() string rewrite with an AST transform (P1)

**Why:** `rewriteInputCalls` in `src/runner/worker.ts` (~lines 51–84) detects
"inside a string" by counting unescaped quotes before the match. It breaks on:
comments containing an apostrophe (`# don't`), triple-quoted strings,
f-strings with nested quotes, and a user variable named `input`. Kids write
exactly this code; the failure is a baffling error in code they didn't write.

Design — move the rewrite into Python (the code already enters Pyodide):
1. Add a function to the Python side (a small new module
   `src/assets/python/input_transform.py`, written to Pyodide FS in `init`
   like the others — follow the existing pattern in `initPyodide`):
   - `ast.parse` the user source.
   - Walk the tree; replace every `Call(func=Name(id='input'))` node with
     `Await(Call(func=Name(id='_async_input'), args=..., keywords=...))`.
     Do NOT rewrite calls where `input` is an attribute (`obj.input(...)`) or
     where the name `input` is locally rebound — detecting rebinding is
     optional polish; at minimum, plain `Name` calls only.
   - `ast.unparse` back to source. (Pyodide 0.29 = CPython 3.12+,
     `ast.unparse` available. VERIFY the Python version with
     `pyodide.runPython("import sys; sys.version")` during development.)
   - On `SyntaxError`, return the source unchanged — the existing error path
     (error_hook) will produce the friendly syntax error; the transform must
     never mask it.
   - **Line-number fidelity:** unparse changes formatting, which would break
     the error classifier's line mapping (`error_hook.classify_error` uses
     `_user_code`). Mitigation: after unparse, the transform is only used for
     the EXECUTED code; keep passing the ORIGINAL source as `_user_code` for
     error display, and call `ast.increment_lineno`-style fix only if needed.
     Test what `error_hook` does with a NameError on line 5 of a transformed
     file; if line numbers drift, copy the original line numbers onto
     transformed nodes via `ast.copy_location` before unparse and verify
     again. This is the riskiest part of the phase — write the error-line
     test FIRST.
2. In `worker.ts` `run` handler (~line 670): call the Python transform instead
   of `rewriteInputCalls`. Keep the async-wrapping/`runPythonAsync` execution
   path otherwise identical. Delete `rewriteInputCalls` and its tests once the
   replacement's tests pass.
3. Tests (Python-side, via the existing `tests/unit/graphicsPython.test.ts` /
   `validate_graphics.py` harness — inspect which one actually executes Python
   and follow it):
   - `input("name")` → awaited.
   - `input("x").strip()` → `(await _async_input("x")).strip()`.
   - `# don't` comment + `input()` on next line → still transformed (the old
     code FAILED this — make it a named regression test).
   - `s = "input(fake)"` → string untouched.
   - triple-quoted string containing `input(` → untouched.
   - NameError on a known line in a program that also uses `input()` →
     friendly error reports the ORIGINAL line number.

**Acceptance:** all above tests green; manual check in IDE: an interactive
input program still prompts and resumes; gate green.
